# 04. 기본 네비게이션 엔진

> 트랙패드 제스처·키보드 입력을 문서 트리 위 **커서 이동**으로 바꾸는 엔진. "점자 훑기" UX의 핵심.

## 목적 / 책임

- 입력(트랙패드/키)을 받아 **현재 레벨 내 이동 / 하위 진입 / 상위 복귀**를 수행한다.
- 이동할 때마다 대상 노드를 TTS(05)로 낭독하고, 하이라이트로 화면에 표시한다.
- "지금 어디에 있는지"(레벨·순서)에 대한 공간감을 준다.

## 조작 모델 (plan.md §3.2)

| 입력 | 동작 |
|---|---|
| 좌 → 우 / 위 → 아래 훑기 | 같은 레벨 노드 순회(이전/다음) |
| 스페이스(또는 지정 제스처) | 선택 노드의 **자식 레벨 진입** |
| 반대 제스처/키 | **상위 레벨 복귀** |
| 실행 키(상호작용 노드에서) | 액션 실행기(07) 호출 |

- 손가락 위치 ↔ 노드 순서를 매핑해 공간감을 제공한다.

## 핵심 설계

- 엔진은 **커서 상태**(현재 노드·레벨)만 소유하고, 트리(03)는 읽기 전용으로 참조한다.
- 제스처 해석(좌표 → 노드)은 셸 입력 계층에서 **정규화된 이벤트**로 받는다 → 코어는 트랙패드 원본 이벤트를 모른다.
- 소수의 직관적 제스처만으로 전체 탐색이 되게 해 학습 곡선을 낮춘다.
- LLM 명령 엔진(06)과 **같은 커서를 공유**한다("로그인창으로 가줘" 후 그 지점에서 훑기 계속).

## 1차 구현

- 코어의 `NavigationEngine`이 트리와 분리된 커서 ID만 보관한다. `next`/`previous`는 같은 부모의 형제 사이를 이동하고, `enter`는 첫 자식으로 진입하며, `back`은 부모로 복귀한다.
- 경계에서는 순환하지 않는다. 대신 `boundary` 결과를 반환해 셸이 효과음·TTS 등으로 끝을 알려줄 수 있다.
- SPA 재추출로 스냅샷이 바뀌면 같은 `id`의 노드를 유지한다. 노드가 사라진 경우 가장 가까운 살아 있는 조상, 마지막 폴백으로 첫 최상위 노드로 이동한다.
- 확장 셸의 임시 키보드 폴백은 `Alt+↓/→`(다음), `Alt+↑/←`(이전), `Alt+Enter`(하위 진입), `Alt+Backspace`(상위 복귀)다. 이동한 노드는 즉시 하이라이트한다. 트랙패드 입력·TTS 연결은 각각 셸 UI와 05 엔진 단계에서 추가한다.

## 의존

- **상류**: 문서 트리(03), 셸의 정규화된 입력 이벤트.
- **하류**: TTS(05), 하이라이트, 액션 실행기(07).

## 범위 / Phase

- Phase 2: 훑기 + 레벨 이동(스페이스) + TTS + 라이브 하이라이트 → 대회 MVP 핵심.

## 미결정 / 리스크

- 트랙패드 좌표 → 노드 매핑 오차·오작동 방지(제스처 정밀도).
- 훑기 속도/민감도는 사용자마다 다르므로 **조정 노브**를 남긴다(기본값은 실사용 피드백으로 튜닝).
- 제스처를 못 쓰는 환경의 키보드 폴백 기본 매핑.
