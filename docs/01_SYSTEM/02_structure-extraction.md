# 02. 구조 추출 엔진

> 라이브 DOM + AX Tree를 **의미적 문서 트리**로 변환하는 파이프라인. 규칙 기반 1차, 신경망은 폴백.

## 목적 / 책임

- CaptureSource(01)가 준 DOM+AX를 받아 **정규화된 문서 트리**(03)를 만든다.
- 마크업이 부실해도 heading 레벨·섹션 경계를 복원한다.
- 광고·반복 내비게이션·푸터 등 본문과 무관한 노이즈를 제거한다.
- **원본 DOM 노드 핸들을 트리 노드에 보존**한다(이후 액션 실행의 전제).

## 파이프라인 (plan.md §3.1)

1. **DOM 수집 + AX Tree 병합** — 시맨틱 태그·ARIA 속성·landmark 추출.
2. **구조 복원** — 규칙 기반(heading/landmark) + 휴리스틱(폰트 크기·굵기·위치·반복 패턴). 실패 시 신경망 폴백.
3. **노이즈 제거** — `@mozilla/readability`류로 본문 분리.
4. **정규화 트리 출력** — 레벨(H1~H6 상당)·텍스트·상호작용 노드(링크·버튼·입력창).

## 도구 선택 — 규칙 1차, 신경망 폴백 (plan.md §3.1)

| 경로 | 도구 | 언제 | 제약 |
|---|---|---|---|
| **1차** | heading/landmark 파서 + `@mozilla/readability` | 항상 | 결정론적·빠름, **DOM 핸들 보존** → 액션 가능 |
| 폴백 | `ReaderLM-v2`(로컬) | 마크업 불량 | CC-BY-NC(비상업)·GPU 필요·수십 초·**DOM 핸들 소실 → 낭독 전용, 액션 불가** |
| 벤치 전용 | `r.jina.ai`(호스티드) | 오프라인 코퍼스 채점만 | 인증 페이지 외부 전송·세션 무관 재fetch → **런타임 금지** |

## 핵심 설계

- 1차 경로가 **라이브 DOM 노드 참조를 그대로 보존**하는 것이 핵심 — 액션 실행기(07)가 같은 핸들을 쓴다.
- 폴백 트리는 핸들이 없으므로 트리 모델(03)에서 "낭독 전용"으로 표시(액션 차단).
- SPA: `onMutation` 시 재추출. 전체 재파싱 회피(증분 갱신)는 Phase 3 과제.

## 의존

- **상류**: 브라우저 인터페이스(01) — `getDOM`/`getAXTree`/`onMutation`.
- **하류**: 문서 트리 모델(03).

## 범위 / Phase

- Phase 1: 규칙 기반으로 잘 마크업된 페이지의 문서 트리 생성·콘솔 검증.
- Phase 3: 휴리스틱 + LLM 보정, 노이즈 제거 강화(벤치 코퍼스로 배치 검증).

## 미결정 / 리스크

- 폴백 트리거 기준: 규칙 기반 결과가 언제 "실패"인지(heading 수·본문 비율 등 지표).
- SPA 증분 갱신 전략(변경 부분만 재추출).
- 마크업 나쁜 실제 사이트의 트리 품질 — 다양한 코퍼스로 벤치마크 필요.
