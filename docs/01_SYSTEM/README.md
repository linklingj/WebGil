# 시스템 설계 문서 (docs/system)

WebGil을 단위 엔진으로 나눈 기획 문서. 전체 기획은 [`../00_PLAN/plan.md`](../00_PLAN/plan.md)이고, 여기서는 각 단위의 **책임·인터페이스·범위**를 구체화한다. 코드 시그니처는 **설계 초안**이며 구현 시 확정한다.

## 데이터 흐름

```
[웹페이지]
  └─ 01 브라우저 인터페이스(CaptureSource) ── DOM + AX Tree
       └─ 02 구조 추출 엔진 ── 규칙 1차 / 신경망 폴백
            └─ 03 문서 트리 모델 ── 레벨·텍스트·핸들
                 ├─ 04 네비게이션 엔진 ◀ 트랙패드/키
                 │    ├─ 05 TTS 엔진 (로컬/API)
                 │    └─ 07 액션 실행기 ─▶ 01.execute()
                 └─ 06 LLM 명령 엔진 (로컬/API) ─▶ 04 커서 / 07 액션 / 05 낭독
```

## 단위 문서

| # | 문서 | 책임 | 위치 | Phase |
|---|---|---|---|---|
| 01 | [브라우저 인터페이스](01_capture-source.md) | 페이지 접근·관찰·제어의 유일한 교체 지점 | core 인터페이스 + 셸 | 1·2·6 |
| 02 | [구조 추출 엔진](02_structure-extraction.md) | DOM+AX → 문서 트리 변환 | core | 1·3 |
| 03 | [문서 트리 모델](03_document-tree.md) | 정규화된 계층 자료구조 | core | 1 |
| 04 | [기본 네비게이션 엔진](04_navigation.md) | 제스처/키 → 커서 이동 | core | 2 |
| 05 | [TTS 엔진](05_tts.md) | 텍스트 → 음성(로컬/API) | core | 2·5 |
| 06 | [LLM 명령 엔진](06_llm-command.md) | 자연어 → 액션(로컬/API) | core | 4 |
| 07 | [액션 실행기](07_action-executor.md) | 액션 → 원본 페이지 트러스트 실행 | core → 01 | 2·4 |

## 한 페이지가 음성이 되기까지

1. **01**이 라이브 DOM+AX를 읽는다.
2. **02**가 규칙 기반으로 문서 트리를 만들고 원본 노드 핸들을 보존한다.
3. **03** 트리에서 사용자가 **04**로 최상위 레벨을 훑는다.
4. 이동한 노드를 **05**가 낭독하고 화면에 하이라이트한다.
5. "로그인창 눌러줘"는 **06**이 노드를 지목 → **07**이 `01.execute()`로 실행한다.

## 설계 규칙

- 모든 단위는 **셸을 모른다**(01 인터페이스에만 의존). 새 셸 = 01 구현 1개 + 셸 마운트.
- 트리(03)는 읽기 전용 스냅샷, 가변 상태(커서)는 네비게이션(04)이 소유한다.
- TTS(05)·LLM(06)은 각자 인터페이스라 로컬/API를 코드 수정 없이 교체한다.
