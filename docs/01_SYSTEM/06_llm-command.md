# 06. LLM 명령 엔진

> 자연어 명령을 문서 트리 위 액션으로 바꾼다. "로그인창 들어가줘" → 요소 탐색·실행.

## 목적 / 책임

- 사용자 자연어를 받아 **의도 해석 → 대상 노드 탐색 → 액션 생성**을 한다.
- 요약·질의도 처리한다("가격 정보 요약해줘", "이 페이지에 로그인 폼 있어?").
- **로컬·API LLM을 `base_url` 교체만으로 스위칭**한다(OpenAI 호환 엔드포인트).

## 입력 / 출력

- **입력**: 자연어 명령 + 문서 트리(03) 스냅샷(노드 `id`가 붙은 텍스트 접근성 뷰).
- **출력** 중 하나:
  - (a) 커서 이동 지시 → 네비게이션(04),
  - (b) `Action` → 액션 실행기(07),
  - (c) 낭독할 답변 텍스트 → TTS(05).

## 핵심 설계 (plan.md §3.4, reference.md B)

- 트리를 **텍스트 접근성 스냅샷**으로 LLM에 준다(vision 불필요·저토큰; Playwright MCP의 `@ref` 패턴과 동일).
- LLM은 자유 클릭이 아니라 **트리 노드 `id`를 지목**하고, 실행은 결정론적 액션(07)이 맡는다(안전·재현성).
- 로컬(Ollama)·API(OpenAI/Anthropic) 모두 OpenAI 호환이라 코드 수정 없이 전환된다.

## 가드레일 (plan.md §6 Phase 4)

- 민감정보(비밀번호 등)는 **로컬 모델 강제**, 외부 전송 금지.
- CAPTCHA/2FA는 사용자에게 인계한다.
- 제출·결제 등 **되돌리기 어려운 액션은 실행 전 확인**한다.
- 교차출처 로그인 위젯은 `all_frames` + host 권한으로 보강한다.

## 답변은 화면이 아니라 스피커로 나간다

- 답변(`answer`)·되묻기(`clarify`) 문구는 **낭독 전용**이다. 마크다운 제목·목록 기호·강조는 TTS가 "별표"·"우물 정"으로 읽거나 문장을 어색하게 끊는다.
- 그래서 프롬프트에 규칙을 넣는다: 사용자의 언어로, 말하듯 한 문단, 서식·이모지·URL 없이, **250자 이내**로 완결된 문장.
- 프롬프트만으로는 모델이 어길 때가 있어 검증 단계(`toSpokenReply`)에서 한 번 더 보장한다 — 서식을 벗기고, 길면 **문장 끝에서** 자른다(말이 중간에 끊기면 답을 못 들은 것과 같다). 문장 끝이 너무 앞이면 말줄임으로 마무리한다.
- 250자는 낭독 시간 기준이다(일반 속도로 약 20초). 더 긴 답은 "가장 쓸모 있는 한 가지"를 말하게 한다.

## 의존

- **상류**: 문서 트리(03), 사용자 명령 입력.
- **하류**: 네비게이션(04) 커서, 액션 실행기(07), TTS(05).

## 범위 / Phase

- Phase 4: 자연어 요소 탐색·액션 실행 + 로컬/API 스위칭 + 가드레일.

## 미결정 / 리스크

- 로컬 모델 성능 vs API 지연·비용 균형(기본 엔진 선택).
- 큰 페이지의 스냅샷 토큰 예산(트리 잘라내기·관련 서브트리만 전달).
- 오작동 액션 방지를 위한 확인 UX 기본값(어디까지 자동, 어디부터 확인).
