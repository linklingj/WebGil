# 08. 사이드패널 UI (확장 셸의 화면)

> 확장 프로그램의 **유일한 화면**. 상단 검색창 + 트리 그래프 뷰 + 도움말·설정 다이얼로그.
> 지금의 popup(설정 전용)은 이 패널로 흡수하고 삭제한다.

## 목적 / 책임

- 코어가 만든 문서 트리(03)를 **보이는 형태**로 제시하고, 사용자의 **현재 위치를 항상 화면 중앙에 확대**해 둔다.
- 키·제스처를 모르는 사용자도 마우스·터치로 같은 탐색을 할 수 있게 한다(입력 경로 추가, 대체 아님).
- 검색·자연어 명령·설정·도움말을 한 화면에 모은다.
- **패널은 셸 코드다.** 코어(02~07)는 패널의 존재를 모른다. 패널은 뷰와 입력만 담당하고, 트리·커서·TTS·액션의 소유권은 그대로 콘텐츠 스크립트에 있다. (plan §4.1)

## 왜 popup이 아니라 사이드패널인가

| | popup | 사이드패널 |
|---|---|---|
| 페이지 조작 중 유지 | 포커스를 잃으면 **닫힘** | 탭 옆에 상주 |
| 페이지와 공존 | 페이지 위를 덮음 | 나란히 배치, 본문 안 가림 |
| 확장 컨텍스트 | 예 | 예 (동일) |

탐색 내내 떠 있어야 하는 트리 뷰에 popup은 구조적으로 맞지 않는다. 설정 화면 하나 때문에 popup을 남겨둘 이유도 없다 — **popup(`popup.html`/`popup.ts`)은 없애고 설정은 패널 안의 다이얼로그로 흡수한다.** 툴바 아이콘을 누르면 popup 대신 패널의 설정 창이 뜬다.

사이드패널도 popup과 같은 **신뢰된 확장 컨텍스트**라 `chrome.storage.local`의 `TRUSTED_CONTEXTS` 접근 레벨이 그대로 유효하다 → **API 키 취급 방식과 background 코드는 바뀌지 않는다.** 설정 화면이 popup에서 패널로 옮겨가도 키의 보관·사용 경로는 동일하다.

## 화면 구조

```
┌────────────────────────────────┐
│ 🔍 [ 검색 / 명령 입력        ] │ ← 상단 고정
│    ├ 결과 1 · 본문 > 공지       │
│    └ 결과 2 · 메뉴 > 로그인     │   (입력 중에만 펼침)
├────────────────────────────────┤
│              ○ 상위             │
│              │                  │
│         ●━━━━◉━━━━●            │ ← 트리 그래프 캔버스
│         형제  현재  형제         │   현재 노드 중심 확대
│              ├── ○ 자식         │
│              └── ○ 자식         │
├────────────────────────────────┤
│ 공지사항 · 레벨 2 · 3/7         │ ← 상태 줄 (aria-live)
│ [?] 도움말        [⚙] 설정      │
└────────────────────────────────┘
```

- 세 영역 모두 키보드만으로 왕복 가능(`Tab` / `Shift+Tab`), 순서는 검색창 → 트리 → 하단 버튼.
- 패널 최소 폭은 브라우저가 정하는 ~320px 기준으로 설계한다.

## 그래프 렌더링 — 무엇을 쓰나

우리 데이터는 임의 그래프가 아니라 **루트가 하나인 트리**고, 노드 편집·드래그가 없다. 그래서 범용 그래프 편집기 대신 트리 레이아웃 계산기를 쓴다.

| 후보 | 판단 |
|---|---|
| **`d3-hierarchy` + `d3-zoom`** | **채택.** `d3.tree()`가 정확히 이 레이아웃. 두 모듈 합쳐 수십 KB, 의존 트리 얕음, ISC(MIT 호환). React 불필요 — 현 스택(순수 TS + esbuild) 그대로. |
| React Flow | React 런타임 전체를 끌고 온다. 노드 편집기용 기능(핸들·엣지 드래그)이 전부 불필요. |
| Cytoscape.js (+dagre) | 그래프 분석용. 번들 크고 트리 레이아웃은 확장 플러그인 필요. |
| vis-network | 캔버스 렌더 → DOM 노드가 없어 접근성 트리를 못 만든다(아래 참조). 물리 시뮬레이션도 불필요. |
| mermaid | 정적 다이어그램 생성기. 커서 추적·부분 렌더에 부적합. |

### DOM 결정: 노드는 HTML, 선만 SVG

**스크린리더 도구의 UI가 스크린리더에 안 읽히면 그 자체로 실패다.** 캔버스 렌더링은 물론이고 SVG `<text>`도 보조공학 지원이 고르지 않다. 그래서 렌더 계층을 쪼갠다.

- `d3-hierarchy`는 **좌표만** 계산한다(렌더 안 함).
- **노드** = 그 좌표에 절대배치한 HTML 버튼. `role="treeitem"`으로 실제 접근성 트리를 구성한다.
- **연결선** = 뒤에 깔린 `<svg aria-hidden="true">`의 `<path>`(`d3.linkVertical()`).
- **카메라** = 노드·선을 함께 담은 컨테이너 하나의 `transform: translate() scale()`. `d3-zoom`이 이 transform을 소유해 휠·핀치·드래그를 처리한다.

## 카메라 — "현재 위치가 확대되어 보인다"

- 커서가 이동할 때마다 대상 노드를 뷰포트 중앙으로 옮기고 배율을 기본값(1.0)으로 되돌린다. 부모 1단계·형제·자식 1단계가 함께 보이는 배율을 기본으로 잡는다 — 현재 위치의 **맥락**이 보여야 공간감이 생긴다.
- 전환은 200ms ease. `prefers-reduced-motion: reduce`면 애니메이션 없이 즉시 점프한다.
- 사용자가 직접 팬·줌하면 자동 카메라를 **일시정지**하고, `Home` 키 또는 "현재 위치로" 버튼으로 복귀한다. 자동으로 뷰를 다시 뺏지 않는다.
- **부분 렌더**: 현재 노드의 조상 경로 + 형제 + 자식 1단계만 그린다. 수천 노드짜리 페이지를 통째로 레이아웃하지 않기 위한 의도적 제한이다.

## 상단 검색창 (내비게이션 검색)

하나의 입력창이 두 가지를 처리한다.

1. **트리 검색(기본)** — 입력할 때마다 트리 텍스트를 부분 일치로 훑어 결과 목록을 보여준다. 각 결과에 조상 경로("본문 > 공지사항")와 레벨을 함께 표시한다. `↑`/`↓`로 이동, `Enter`로 그 노드에 커서를 점프시킨다. LLM을 쓰지 않으므로 즉시·오프라인·무료다.
2. **자연어 명령** — `?`로 시작하거나 일치 결과가 없으면 06 LLM 명령 엔진으로 넘긴다. 확인이 필요한 명령의 확인 흐름은 기존 것을 그대로 쓴다.

- 코어에 필요한 추가는 검색 함수 하나(`searchTree(tree, query)`)뿐이다.
- 페이지 안에 오버레이로 띄우던 명령 팔레트(`Alt+Shift+L`)는 이 입력창으로 통합한다. 단축키는 "패널 검색창에 포커스"로 의미만 바뀐다 → **원본 페이지에 주입하는 UI가 하나 줄어든다.**

## 도움말 / 설정

둘 다 **네이티브 `<dialog>`**로 연다. 포커스 트랩·`Esc` 닫기·배경 비활성화를 브라우저가 이미 제공하므로 모달 라이브러리를 넣지 않는다.

**설정** (popup에서 이관 + 추가)

| 항목 | 저장 키 | 비고 |
|---|---|---|
| LLM 제공자 / 모델 / API 키 | `webgil.llm.provider` | popup과 동일 스키마 |
| ElevenLabs API 키 / Voice ID / 모델 | `webgil.tts.elevenlabs` | popup과 동일 스키마 |
| 낭독 속도·상세도 | (신규, 미구현) | 아래 "아직 안 한 것" |
| 터치 네비게이션 기본값 | (신규, 미구현) | 현재는 매번 `Alt+Shift+T` |

저장 키와 스키마를 그대로 두면 **background는 한 줄도 안 고쳐도 되고, 기존 사용자의 설정도 그대로 살아난다.** API 키 경고 문구(외부 전송 범위)도 함께 옮긴다.

**설정 다이얼로그의 진입점은 둘이다.**

1. **툴바 아이콘 클릭** — popup을 띄우지 않는다. 사이드패널을 열고(닫혀 있었다면) **그 안의 설정 다이얼로그를 연다.** 지금 popup으로 하던 일이 그대로 패널 안으로 들어온다.
2. 패널 하단의 `[⚙] 설정` 버튼.

두 경로 모두 같은 다이얼로그를 열고, 열림 요청은 한 가지 방식으로만 전달한다(아래 [설정 창 여는 경로](#설정-창-여는-경로)).

**도움말** — 단축키·제스처 표. 문자열은 셸의 단축키 정의 한 곳에서 가져와, 표와 실제 동작이 어긋날 여지를 없앤다.

## 패널 ↔ 페이지 통신

패널은 콘텐츠 스크립트와 **다른 컨텍스트**다. 여기서 생기는 제약이 이 설계의 핵심 제약이다.

```
[사이드패널]                          [콘텐츠 스크립트 = 코어 소유자]
  검색·클릭·설정  ──chrome.tabs.sendMessage──▶  NavigationEngine / ActionExecutor
  트리 렌더·카메라 ◀──chrome.runtime.sendMessage──  트리 스냅샷 · 커서 변경
```

- **패널 → 콘텐츠**: `next` / `previous` / `enter` / `back` / `moveTo(id)` / `activate(id)` / `rescan` / `refine`.
- **콘텐츠 → 패널**: 트리 스냅샷, 커서 변경(현재 id·인덱스·형제 수).
- **직렬화 경계 (중요)**: `DocNode.handle`은 DOM Element라 메시지로 복제되지 않는다. 전송용으로 `id`/`kind`/`level`/`text`/`regionRole`/`children`만 담은 **스냅샷**을 보낸다(코어에 `toSnapshot(tree)` 하나 추가). 패널은 `id`만 알고 `id`로 명령만 보낸다 → 복제 문제와 "화면 계층에 DOM 핸들을 넘기지 않는다"는 보안 원칙이 동시에 해결된다.
- **갱신**: SPA mutation 재추출과 탭 전환(`chrome.tabs.onActivated`) 시 패널이 스냅샷을 다시 받는다. mutation 폭주에 대비해 스냅샷 전송은 초당 횟수를 제한한다.
- 콘텐츠 스크립트가 없는 탭(`chrome://`, 웹스토어 등)에서는 패널이 "이 페이지에서는 사용할 수 없습니다" 상태를 보여준다.

### manifest 변경

```jsonc
"permissions": ["storage", "sidePanel", "tabs"],
"side_panel": { "default_path": "panel.html" },
"action": { "default_title": "WebGil 설정 열기" }   // default_popup 제거 = popup 폐기
```

`default_popup`을 빼면 `popup.html`이 더는 뜨지 않고, 대신 `chrome.action.onClicked`가 background로 온다. 그 핸들러에서 패널을 연다.

### 설정 창 여는 경로

아이콘 클릭 → 패널 열기 → 설정 다이얼로그. 여기서 걸리는 건 **타이밍**이다. 패널이 방금 열렸다면 아직 스크립트가 부팅되기 전이라 "설정 열어" 메시지를 받을 수신자가 없다. 그렇다고 이미 열려 있던 경우와 방금 연 경우로 코드를 가르면 경쟁 조건이 그대로 남는다.

그래서 **메시지를 쓰지 않고 상태를 쓴다.**

```
[툴바 아이콘 클릭]
  └ background: chrome.sidePanel.open({ tabId })          ← 사용자 제스처 소비, 첫 await
       └ chrome.storage.session.set({ "webgil.panel.view": "settings" })
            └ 패널: 부팅 시 1회 읽기  +  storage.session.onChanged 구독
                 └ 값이 "settings"면 다이얼로그 open, 읽은 뒤 값 비움
```

- 패널이 **닫혀 있었으면** 부팅 시 읽기가, **열려 있었으면** `onChanged`가 잡는다. 경로 하나로 두 경우가 다 커버되고 경쟁 조건이 없다.
- `chrome.storage.session`은 기본 접근 레벨이 신뢰된 컨텍스트 전용이라, 페이지·콘텐츠 스크립트에는 이 값이 보이지 않는다. `storage` 권한 외에 추가 권한도 필요 없다.
- `chrome.sidePanel.open()`은 **사용자 제스처 안에서만** 호출된다. `onClicked` 핸들러는 제스처 안이지만 `await`를 거치면 소진될 수 있으므로 **`open()`을 가장 먼저 호출**하고 나머지를 뒤에 둔다.
- 패널 하단 `[⚙]` 버튼은 이 경로를 타지 않고 다이얼로그를 직접 연다(같은 컨텍스트라 우회할 이유가 없다).
- 단축키로 여는 경우도 `commands` 핸들러에서 같은 두 줄을 호출한다.
- `openPanelOnActionClick`은 켜지 않는다. 켜면 Chrome이 클릭을 직접 처리해 `onClicked`가 오지 않고, "설정을 열어라"는 의도를 실을 자리가 사라진다.

## 패널 자체의 접근성 (타협 없음)

- 트리: `role="tree"` / `role="treeitem"` + `aria-level`, `aria-expanded`, `aria-setsize`, `aria-posinset`. 커서는 `aria-activedescendant`로 표현한다(roving tabindex 대신 — 포커스가 컨테이너에 머물러 검색창↔트리 왕복이 단순해진다).
- 상태 줄은 `role="status" aria-live="polite"`.
- 모든 기능은 키보드만으로 도달 가능해야 한다. 마우스 전용 기능을 만들지 않는다.
- 대비 4.5:1 이상, 포커스 링 제거 금지, 클릭 타깃 최소 24px, `prefers-reduced-motion`·`prefers-contrast`·`forced-colors` 대응.
- 패널 UI 언어는 페이지 언어와 무관하게 `lang="ko"`.
- 확대(브라우저 줌 200%)에서도 레이아웃이 깨지지 않아야 한다.

## 1차 구현 범위

```
apps/extension/src/panel/
  panel.html      레이아웃 + 두 개의 <dialog>
  panel.css       테마·대비·reduced motion
  panel.ts        진입 — 메시지 구독, 조립, 키보드
  protocol.ts     패널 ↔ 콘텐츠 메시지 규약(양쪽이 함께 import)
  tree-view.ts    d3-hierarchy 레이아웃 + 카메라 + 부분 렌더
  search.ts       검색 / 자연어 명령 입력
  settings.ts     popup.ts 이관
  help.ts         SHORTCUTS 렌더
```

- `popup.html` / `popup.ts` 삭제, `build.mjs` 엔트리를 패널로 교체(빌드 산출물은 `dist/panel/`).
- 코어에 추가된 건 `toSnapshot()`·`searchTree()`(03)와 `NavigationEngine.moveTo()`·`position`(04)뿐이다.
- 새 런타임 의존: `d3-hierarchy`, `d3-zoom`, `d3-selection` (ISC). `d3-shape`·`d3-transition`은 넣지 않았다 — 링크 path는 한 줄이고, 200ms 이징은 CSS `transition`이 한다.
- 검증: `prune()` 규칙 단위 테스트 + 진짜 `panel.html`을 jsdom에 띄우는 스모크 테스트(선택자·역할 속성이 코드와 어긋나면 실패).

**아직 안 한 것** — 설정 표의 "신규" 3줄 중 낭독 속도·터치 네비 기본값은 미구현이다. 콘텐츠 스크립트는 `storage.local`(TRUSTED_CONTEXTS)을 읽을 수 없어 값을 전달할 경로부터 정해야 한다. 자동 카메라는 패널 안에서 팬·줌으로 껐다 켜므로 별도 설정을 두지 않았다.

## 의존

- **상류**: 03 문서 트리(스냅샷), 04 네비게이션(커서), 06 LLM 명령, 07 액션 실행기.
- **하류**: 없음 — 패널은 최종 표시 계층이다.

## 범위 / Phase

- Phase 5(다듬기 = 대회 제출본). 설정 UI 요구사항이 여기에 흡수된다.
- Phase 6에서 데스크톱 셸로 갈 때, 패널은 `CaptureSource` 교체와 무관하게 **컴포넌트 마운트만 옮겨** 재사용한다(plan §4.1).

## 미결정 / 리스크

- **노드 수천 개 페이지의 렌더 성능** — 조상+형제+자식 1단계 창(window) 렌더로 시작하고, 부족하면 가상화한다.
- **이중 낭독** — 외부 스크린리더(NVDA/VoiceOver)를 함께 쓰면 패널 UI와 WebGil TTS가 겹쳐 말할 수 있다. 어느 쪽이 말할지 정하는 스위치가 필요할 가능성이 크다. 실사용자 테스트 전까지 결론 보류.
- **좁은 패널 폭** — 가로 트리는 320px에서 읽기 어렵다. 세로(위→아래) 레이아웃을 기본으로 두고 가로는 옵션으로 검토.
- **사이드패널의 탭별 상태** — 탭마다 열림 상태가 갈린다. 전역으로 열어둘지 정책 필요.
- **아이콘 클릭 = 항상 설정**이 반복 사용에서 번거로울 수 있다(패널을 열려던 것뿐인데 매번 모달을 닫아야 함). 대안은 "API 키가 아직 없을 때만 설정을 자동으로 열고, 그 뒤엔 패널만 연다". 초기 설정이 끝난 사용자를 관찰한 뒤 정한다 — 어느 쪽이든 위의 `storage.session` 경로는 그대로 쓴다.
- `d3-zoom`의 휠 처리와 패널 스크롤·브라우저 핀치 줌의 충돌.
